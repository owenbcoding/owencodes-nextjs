-------------------------------------------------------

  RESEND_API_KEY                 required to talk to Resend at all
  RESEND_AUDIENCE_ID             audience contacts get added to
  RESEND_SEGMENT_ID              optional, broadcast segment
  RESEND_WELCOME_TEMPLATE_ID     welcome email on subscribe
  RESEND_KEY                     fallback name for the API key
  SANITY_WEBHOOK_SECRET          REQUIRED - currently missing in production
  MAIL_FROM_ADDRESS              sender, e.g. newsletter@owencodes.dev
  MAIL_FROM_NAME                 sender display name, e.g. Owencodes
  CONTACT_FROM_EMAIL             overrides MAIL_FROM_ADDRESS for contact + newsletter
  NEWSLETTER_NO_REPLY_FROM       no-reply sender for transactional mail
  NEWSLETTER_UNSUBSCRIBE_SECRET  signs unsubscribe links (falls back to NEWSLETTER_SEND_TOKEN)
  NEWSLETTER_SEND_TOKEN          old token, still used as unsubscribe fallback
  MAIL_PASSWORD                  legacy SMTP-era var, unused by Resend

Notes verified by reading the code:
- If MAIL_FROM_ADDRESS is not set, the sender falls back to
  "Owencodes Newsletter <onboarding@resend.dev>". onboarding@resend.dev can only
  send to the Resend account owner's own address, so in practice every real
  subscriber would fail until a domain address is configured.
- If NEWSLETTER_NO_REPLY_FROM is not set, it also falls back to onboarding@resend.dev.
- getSiteUrl() reads NEXT_PUBLIC_SITE_URL, then VERCEL_URL, then localhost.
- SITE_URL (the old GitHub Actions variable) is now unused by the app.
- Sending goes through resend.broadcasts.create({ send: true }), i.e. a real
  broadcast to the whole audience - not a single test email.


4. RESEND DOMAIN / DNS VERIFICATION
-----------------------------------
Verified with node:dns/promises (dig and nslookup are not installed on this machine).
- TXT send.owencodes.dev
    v=spf1 include:amazonses.com ~all                          PRESENT
- MX  send.owencodes.dev
    feedback-smtp.eu-west-1.amazonses.com (priority 0)          PRESENT
- TXT resend._domainkey.owencodes.dev
    p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQDR9I7W...          PRESENT (DKIM)
- TXT _dmarc.owencodes.dev                                      ENOTFOUND
- TXT _dmarc.send.owencodes.dev                                 ENOTFOUND

Meaning: the Resend sending domain (send.owencodes.dev) is set up correctly -
SPF, Amazon SES feedback MX and DKIM are all published, and the sending region
is eu-west-1. DMARC is missing at both the apex and the subdomain, so there is
no policy telling receivers what to do with unauthenticated mail. Mail can still
deliver without it, but adding a start-off policy is recommended:
    _dmarc.owencodes.dev  TXT  "v=DMARC1; p=none; rua=mailto:you@owencodes.dev"
This was not something I changed - DNS is outside this repository.

7. HOW TO TEST SAFELY (single recipient, no mass email)
-------------------------------------------------------
Do not use the production broadcast path for a test - it mails every confirmed
contact in the audience.
  1. Create a SECOND Resend audience, e.g. "newsletter-test", and add only your
     own address to it.
  2. In a preview deployment, point RESEND_AUDIENCE_ID at that test audience and
     set the rest of the vars. Never point production at it.
  3. Publish a draft blog post in Sanity (not in production content) and watch
     the preview deployment logs for the webhook request.
  4. Confirm the email arrives from newsletter@owencodes.dev, not
     onboarding@resend.dev, and that the unsubscribe link resolves.
  5. Delete the test audience and preview env vars afterwards.
